# Organizer rules (Qiskit Fall Fest 2026 hackathon message, verbatim content)

**Submission (all four required):**
- GitHub repository link with working, reproducible Qiskit code
- Report (.docx) with results, the classical/exact comparison and an honest limitations section
- Architecture diagram (included in the report)
- 3-minute video pitch and demo (Google Drive or similar link; access set to "anyone with the link")

**Deadline:** 12 Nov 2026, 11:59pm (organizer's local time; the team is likely on PKT, UTC+5).

**Dos:**
- Keep the instance small and simulator-friendly; real hardware and quantum speedup are not required
- Make the quantum part do real work in your solution, not just decoration
- Include a README with setup steps so judges can run your code
- Be honest about what didn't work; limitations count in your favour
- Check that every link opens before you submit

**Don'ts:**
- Don't pick a problem outside the six domains
- Don't submit code copied from tutorials or other teams; reused code must be credited
- Don't go over 3 minutes on the video
- Don't push commits after the deadline; the last commit before the cutoff is what gets judged

**Judging rubric (100):**
- A. Problem validity, 20: relevance (5), clear formulation (5), scope and feasibility (5), measurable objectives and constraints (5)
- B. Meaningful quantum use, 25: correct mapping to a quantum representation (10), suitability and justification of algorithm (10), quantum computation materially used plus awareness of assumptions and limits (5)
- C. Implementation and validation, 25: working Qiskit code (10), outputs people can read (5), valid classical/exact/analytical baseline (5), reproducibility (5)
- D. Innovation and originality, 15: originality of the problem in its domain (10), thoughtful adaptation, modeling or technical extension (5)
- E. Presentation and defense, 15: clarity (10), demo quality and answers to technical questions (5)
